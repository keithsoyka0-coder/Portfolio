1 · Scope Summary

This spec describes the Phase-2a implementation plan for a 4-page static marketing site for the fictional Los Pollos Hermanos franchise group. The site supports the two fictional engagement goals: driving catering quote requests and franchise inquiries, while letting a non-technical manager update menu items and locations without rebuilding the site.

PageFilePrimary job
Homeindex.htmlFirst impression; brand sell; route visitors to Menu, Locations, Contact
Menumenu.htmlScannable food listing with prices (all fictional), allergen note
Locationslocations.htmlFind-us cards for 3 fictional locations + "coming soon" notice
Contactcontact.htmlCatering quote form → fictional inbox; franchise inquiry block; 4-question FAQ
Static by design. No server, no database, no CMS backend. The site is HTML + CSS + a small JS file, editable in plainly-marked regions. Fast on phones, cheap to host, nothing to patch at 3am.

2 · Phased Build Plan

The build runs in five phases, each ending in something the client can see and approve before the next begins.

PHASE 1 — SETUP & TOKENS
  • Scaffold project: 4 HTML files, styles.css, script.js, assets/ for SVG illustration.
  • Encode the full token set from brief §5 as CSS custom properties (:root block). Zero hardcoded hex colors anywhere else.
  • Set type scale: Oswald headings, Inter body, Caveat for taglines only; system stacks as the live fallback.
  • Define shared shells: sticky header component, footer component, SAMPLE banner ribbon.
PHASE 2 — PAGES & CONTENT
  • Home: red sunburst hero with invented tagline, dual CTA (View Menu / Request Catering), 3 value props (family recipe · immaculate dining rooms · catering), featured menu teaser, locations teaser.
  • Menu: 3 category cards (Chicken · Sides · Drinks & Desserts) with all fictional prices; allergen note.
  • Locations: 3 fictional location cards — Albuquerque NM (Central Ave — Flagship), Santa Fe NM, El Paso TX — each with fictional address, Mon–Sun 10am–10pm hours, phone, "Get directions" link; "New location coming: Tucson AZ" notice.
  • Contact: catering quote form (name, email, event date, guests, message), franchise inquiry block (separate email link), 4-question FAQ (catering minimums, franchise info, allergens, hours).
PHASE 3 — COMPONENTS & INTERACTION
  • Header: sticky, red, logo badge + nav + "Order Catering" CTA pill button.
  • Contact form: labels above inputs, inline validation (JS), friendly error/success states; submits to the fictional inbox (no real backend in the sample).
  • FAQ accordion: keyboard-operable, expands/collapses with aria attributes.
  • Stripe/sunburst CSS motifs, illustrated chicken badge, stripe dividers — CSS/SVG only, no photos.
PHASE 4 — QA & ACCESSIBILITY
  • Layout verified at 360px and 1280px; no horizontal scroll anywhere.
  • WCAG 2.1 AA contrast checked on every text/background pairing in the token set.
  • Keyboard navigation: nav, accordion, form all reachable and operable without a mouse; visible focus styles.
  • Spellcheck, link check, and a mobile load pass (imagery is CSS/SVG, so pages stay light).
PHASE 5 — HANDOFF
  • Editable regions clearly marked in the code (see §4) so a non-technical manager can find them.
  • Provenance envelope line on every file: © 2026 Keith Soyka / GestaltView · SAMPLE.
  • Handoff walkthrough + the §7 checklist signed off with the client.

4 · Technical Approach

4.1 Stack

Plain static HTML + CSS + one small JS file. No framework, no build step, no server. Rationale: the brief demands speed on mobile, near-zero hosting cost, and maintainability by a non-technical manager — a static site meets all three; anything heavier would be over-engineering.

4.2 Token-driven CSS

All six LPH colors live as CSS custom properties in one :root block (--lph-red, --lph-yellow, --lph-cream, --lph-brown, --lph-orange, --lph-red-dark). No hex values outside that block — so a rebrand is a six-line change. Spacing uses the 8px base unit; buttons are pill radius (999px); cards are 12px radius.

4.3 Editable regions

Menu items and locations are wrapped in plainly-marked HTML comments a non-technical manager can find, e.g.:

<!-- ★ EDITABLE: MENU ITEMS — copy a block to add one ★ -->
<!-- ★ EDITABLE: LOCATIONS — copy a card to add one ★ -->

Each menu item and each location card is one self-contained, copy-pasteable block. The handoff walkthrough opens the file in a text editor and demonstrates an actual edit.

4.4 Imagery

No photos anywhere — brand is carried by CSS/SVG illustration (sunburst hero, chicken badge, stripe dividers) per the brief. This also keeps mobile load times trivial.

4.5 Accessibility baseline

WCAG 2.1 AA contrast on all text pairings; semantic HTML landmarks; keyboard-navigable nav, accordion, and form; visible focus indicators; English copy only.

6 · Exclusions — What Is NOT Included

Per brief §3, the following are out of scope, stated plainly so there are no surprises:

  • No online ordering. No cart, no checkout, no order tracking.
  • No payments. No card processing, no invoices.
  • No accounts. No sign-up, no logins, no member areas.
  • No real photography — illustration and typography carry the brand.
  • English copy only; no multilingual versions in this phase.
  • 4 pages only. Additional pages (blog, careers, press) are a future phase.
What happens instead: the catering form collects quote requests and routes them to the fictional inbox — that is the conversion path. Ordering and payments can be scoped as a separate engagement later.
