3. Constraints (From Brief)

  • 4 pages only: Home, Menu, Locations, Contact.
  • No online ordering, no payments, no accounts. Explicitly out of scope — stated plainly so scope stays bounded.
  • No real photography available. The brand must be carried by CSS/SVG illustration and typography (sunburst hero, illustrated chicken badge, stripe dividers).
  • WCAG 2.1 AA contrast required on all text. Copy in English only.
  • Handoff must be maintainable by a non-technical manager — menu items and locations editable in plainly-marked spots, without code changes.
  • Design token set is fixed: LPH red #B3122E, yellow #FFC72C, cream #FFF6E5, brown #4A2C1A, orange #E87722, red-dark #7E0C20. No hardcoded colors outside these tokens.

4. Key Findings

What discovery surfaced that the spec phase must act on:

1

Two conversions, two audiences — one site must serve both

The site's success is measured by catering quote requests and franchise inquiries — two distinct visitor intents. Catering visitors are event planners seeking trust and appetite appeal; franchise visitors are investors seeking legitimacy and a clear path to contact. Both conversion paths must be present and unambiguous, with the Contact page carrying catering as the primary form and the franchise inquiry as a distinct, separate block (not a variant of the same form).

Design impact: dual-CTA hero ("Order Catering" + franchise path); Contact page split into two clearly-separated conversion zones.
2

Mobile-first audience — performance is a first-class requirement

Most visitors arrive from social and maps on phones. This is not a "responsive afterthought" situation: the design and performance budgets must be set mobile-first, with a fast first paint on mid-range devices over mobile connections. Every design choice — illustration complexity, font loading, form widgets — gets judged against load time.

Design impact: mobile-first layout spec; performance budget defined in the Implementation Spec before any design work begins.
3

No photography → the brand must live in CSS/SVG and type

No real photography is available, so "appetizing" must be delivered through illustration and typography alone: a sunburst hero, an illustrated chicken badge, retro-diner diagonal-stripe motifs, and a confident type pairing (Oswald headings, Inter body, Caveat for the tagline). The risk is a site that feels empty or generic; the mitigation is treating the illustrated brand system as a first-class deliverable, not decoration.

Design impact: an illustrated brand component set (badge, sunburst, stripe dividers) becomes part of the design spec; no placeholder image slots that imply "photo goes here."
4

A non-technical manager must edit menu and locations — maintainability is a feature

The person maintaining this site is not a developer. Menu items (with prices, allergen note) and locations (addresses, hours, phones, "coming soon" announcements) must live in plainly-marked, clearly-labeled regions that a non-technical manager can find and edit without touching layout or logic. This is an acceptance criterion for "done," so the implementation must be structured for it from the start — not retrofitted.

Design impact: content regions explicitly zoned and labeled in the implementation spec; the handoff includes a short plain-language editing guide.
5

Scope is intentionally narrow — keep it that way

The brief explicitly excludes online ordering, payments, and accounts. These are the most likely scope-creep vectors (a "can't we just add a cart?" conversation). Discovery confirms the exclusions are deliberate and should be carried forward as stated constraints into the spec phase, with the 4-page structure treated as a hard boundary.

Design impact: the Implementation Spec restates out-of-scope items explicitly; any future addition is a new engagement, not an expansion.

6. Recommended Direction Into Spec Phase

The one-sentence read

This is a trust-and-conversion site, not a catalog or a store: four pages whose entire job is to make a catering planner hungry and confident, give a franchise prospect a clear door to knock on, and let a non-technical manager keep it alive afterward.

Spec-phase priorities (in order)

  1. Lock the conversion architecture first: dual-CTA routing on every page; Contact page split into catering form (name, email, event date, guests, message) and a separate franchise inquiry block; 4-question FAQ (catering minimums, franchise info, allergens, hours).
  2. Define the illustrated brand system: chicken badge, sunburst hero, stripe dividers — as named, reusable components, with the no-photography rule enforced (no empty "image goes here" slots).
  3. Zone the manager-editable regions: menu items/prices/allergen note and the three locations (+ Tucson "coming soon") as plainly-marked, isolated content regions; pair with a plain-language editing guide at handoff.
  4. Set the mobile performance budget and AA contrast checks as acceptance gates: 360px and 1280px verified, no horizontal scroll, keyboard-navigable nav and form.
  5. Restate the hard boundaries: 4 pages, no ordering/payments/accounts — carried verbatim from discovery into the Implementation Spec.
